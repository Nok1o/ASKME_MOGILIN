# Внесение изменений

## Рабочий процесс

1. Создайте отдельную ветку от актуальной `main`.
2. Подготовьте небольшое логически цельное изменение.
3. Добавьте или обновите тесты и документацию.
4. Выполните локальные проверки.
5. Откройте pull request с описанием причины и способа проверки.

## Локальные проверки

```bash
python manage.py check
python manage.py test
python -m compileall app askme_mogilin
```

Для изменений моделей создавайте миграции командой `python manage.py makemigrations`
и включайте их в тот же pull request. Не редактируйте уже применённые миграции.

## Соглашения

- не добавляйте секреты, `.env`, локальную базу и пользовательские загрузки;
- используйте переменные окружения для настроек конкретного окружения;
- сохраняйте представления тонкими, а повторяемую бизнес-логику выносите в
  формы, модели или отдельные сервисы;
- для новых маршрутов добавляйте имя (`name`) и тест хотя бы основного сценария;
- отдельно отмечайте изменения схемы базы и несовместимые изменения.

## Pull request

В описании укажите:

- что изменено и зачем;
- как воспроизвести или проверить результат;
- нужны ли миграции или новые переменные окружения;
- скриншоты для заметных изменений интерфейса.
